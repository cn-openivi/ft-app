**Статус:** TLS/SPAKE2, mDNS, RemoteInput, одноразовое чтение Accessibility и SuperCast уже интегрированы в исходники FT182. НЕ собран, НЕ выполнены Gradle/CI/Android runtime/HU проверки. Полноценная работа на реальном телефоне пока НЕ подтверждена.
**FT181 исходник:** a99ed721053c2b976d14cadbd98388fc6bbb4a0f.

## Актуализация после аудита FT182 (13.11.2026)
- HEAD после source-only исправлений: `0ff7f4934d7aeeffc87b65e55f9efe804de8b01b` (см. следующие коммиты этой ветки, HEAD может изменяться). Зафиксировано отдельно в отчёте Google Drive.
- В `MainActivity` закрыта уязвимость экспортируемых непроверенных extras: старые команды `adb shell am start ... --ez supercast`, `off`, `wifi`, `aa` и подобные больше не являются допустимой внешней точкой управления. Поддерживается только внешний `ft://look` для обмена оформлением. Существующие штатные кнопки FT остаются.
- Для TLS исправлен ошибочный getter сертификата BouncyCastle. SuperCast отслеживает завершение процесса помощника через Binder death; обнаружение mDNS прекращается после асинхронного позднего старта; окно foreground-поиска сопряжения ограничено 120 секундами.
- Бэкап не экспортирует `supercastToken`, `aaVehicleId`, `carWpsPin`; успешная запись в файл больше не определяется при null-output-stream.
- Разрешения на соединение теперь запрашиваются по нажатию включения, медиа — по отдельной кнопке на телефоне. Результат открытия медиатеки обновляется на ГУ. Пожизненную работоспособность OEM-UI/уведомлений это НЕ доказывает.
- Строки калибровки ICCOA/«Всегда P» локализованы; переключатель стрелок на приборке показан только в CarLife, потому что ICCOA Control11 не доказывает поддержку кластера.
- По-прежнему OPEN: совместимость SPAKE2/TLS/mDNS с телефонами производителей и авто; второй Launcher Activity внутри одного пакета (потребует отдельной миграции маршрутов запуска и выбора компонентов). НЕ запускались Gradle, JUnit, CI, эмулятор, HU.
- API Android `Settings.ACTION_APPLICATION_DEVELOPMENT_SETTINGS` открывает Developer Options, а не гарантированно диалог кода сопряжения; пользователь должен вручную открыть Wireless debugging → Pair device with pairing code. Прямой стабильный публичный Intent этого диалога не подтверждён. Никаких выдуманных системных activity/port.

**Владелец:** для обычного пользователя никакого разделённого экрана и ручных портов; запрос 2026-11-13.

## Рекомендованная последовательность

1. В FT кнопка «Настроить приложения в автомобиле» объясняет только пользовательские действия и проверяет разрешения.
2. FT сначала проверяет уже существующее сохранённое сопряжение: пробует TLS по **текущему** `_adb-tls-connect._tcp`, не по 5555.
3. Если требуется первоначальное сопряжение, открывается `Settings.ACTION_APPLICATION_DEVELOPMENT_SETTINGS`. До открытия FT запускает mDNS-поиск `_adb-tls-pairing._tcp`, не сохраняет найденный порт. Пользователь включает беспроводную отладку и нажимает «Сопряжение с помощью кода».
4. Если пользователь **явно разрешил** временное чтение кода через уже установленную Accessibility FT, FT ограниченно просматривает текст **только** системного Settings-пакета и только пока обнаружен актуальный mDNS pairing endpoint. Таймер <=2 мин, однократное чтение, никакого кода в логах/сохранениях. Это опциональный ускоритель, не универсально доступная функция Android.
5. Если OEM запретил чтение, резерв — уведомление с `RemoteInput` «Ввести 6 цифр» поверх системного окна. Не переключать приложения; не делать split-screen. Перед этим проверить POST_NOTIFICATIONS и background restrictions, чтобы пользователь не застрял без уведомления. Сохранять только доверенный ключ/идентификатор, а не код или pairing-порт.
6. Если и уведомление невозможно (OEM ограничил/System UI не показывает), показать честный остаточный блокер и предложить экспертные варианты: плавающее окно **только если ОС позволяет** или компьютер. Не требовать split-screen на устройстве, которое его не поддерживает.
7. После успешного SPAKE2+TLS pairing искать свежий `_adb-tls-connect._tcp`, сверить доверенную идентичность, отправить helper через проверенный ADB shell, дождаться `SuperCastProvider` binder c проверкой token+UID, только после этого READY.
8. Смена порта/mDNS `onServiceLost` во время диалога — сброс текущей попытки и приглашение открыть новый код; **не** перебирать старые порты/коды. На повторных запусках — заново обнаружить connect-порт. Код нужен обычно один раз; перезагрузка может потребовать повторного запуска helper, не обязательно нового pairing.
9. Никакой фальшивой READY и никакого silent root/WRITE_SECURE_SETTINGS. Секретные коды/ключи/адреса не писать в логи или Drive.

## Изученные решения (проверяемые источники)
- Официальный Shizuku: https://shizuku.rikka.app/guide/setup/ — ввод кода через уведомление, без компьютера.
- RikkaApps/Shizuku: manager/src/main/java/moe/shizuku/manager/adb/AdbMdns.kt, AdbPairingService.kt — mDNS и RemoteInput.
- thejaustin/ShizukuPlus: manager/src/main/java/af/shizuku/manager/adb/AdbPairingAccessibilityService.kt — opt-in автоизвлечение кода из системных окон.
- GlassHaven/Haven issue #575: https://github.com/GlassHaven/Haven/issues/575 — в тестах Android 16 уведомление работает при смене временных портов; overlay хуже, потому что системные окна могут скрывать overlay.
- Android ADB: https://developer.android.com/tools/adb — pairing только после разрешения пользователя; не трактовать mDNS как авторизацию.
- TLS/SPAKE2 engine: исходники rhythmcache/adb-kt v1.0.6 + spake2-kt v1.0.2 закреплены в FT (Apache-2.0); upstream trust-all TLS НЕ переносился. Собственный PinnedTlsPacketTransport сверяет отпечаток сертификата с успешно сопряжённым. Компиляция и runtime handshake ещё не подтверждены.

## FT182 текущее исходное исполнение (13 ноября 2026)

- `WirelessAdbDiscovery`: поиск новых временных mDNS pairing и connect портов, только IP локального телефона; stale port сбрасывается при потере сервиса
- `WirelessPairingService`: foreground с уведомлением и RemoteInput для шестизначного кода; при отмене сбрасывается IDLE, подробный код ошибки без записи PIN в лог
- `WirelessPairingAutoCode`: по явному нажатию пользователя один раз читает код из доступного системного Settings окна через уже разрешённый Accessibility, таймаут 90 секунд; ограничение OEM и permission допустимо
- `WirelessAdbEngine`: SPAKE2 pairing, стабильный app-private ключ, pinned peer fingerprint, TLS connect по свежему mDNS порту, id -u=2000 и shell-v2 launch
- `SuperCast.start`: только verified Binder + ping определяет READY; старый порт 5555 допускается только в экспертных настройках и выключен по умолчанию
- `HomeScreen`: 3 разрешения показаны один раз сразу после статуса, RU/EN тексты; `SettingsScreen`: ввод порта/DPI/размеров подтверждается явно
- **Критерии приёмки:** `DOCUMENTED_SCHEMA` подтверждён источником; `SOURCE_COMPARISON` проведён; тесты добавлены, но `NOT_RUN`; `BUILD_NOT_AUTHORIZED`, `HU_NOT_TESTED`, нельзя утверждать PASS
