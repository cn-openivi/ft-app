# FT183 — Wake the physical phone on touch, re-dim after 30 seconds

Owner request: while a phone app is mirrored to an in-car HU, the panel is dimmed to the minimum *physical phone brightness* (not a black overlay and not MediaProjection image brightness). **Any detected physical phone touch** temporarily restores the saved pre-projection brightness without consuming the touch. The timer resets on each further physical phone activity; 30 s after the last detected touch, brightness returns to minimum. As soon as mirroring ends, app restores the exact saved brightness and automatic-brightness mode; no later timer may dim the disconnected phone. No HU button is needed and HU touches are not supposed to wake the phone.

Source version `3.9.69-xa60-ft183-mirror-preview`, display label **OpenIVI FT**, `applicationId=app.ft.xa60` unchanged. This is FT183 only; source and feature must be tested before any optional FTMP transfer.

## Implementation and compatibility
- `MirrorPanelSaver` coordinates manual level 1 while mirroring; persisted original level and auto/manual mode survive app process death, with recovery when FT starts again. During a touch it temporarily sets *the original brightness level* but keeps manual mode, avoiding auto brightness fluctuations. A single main-looper delayed task is rescheduled after each interaction; end cancels the task and restores both originals. No touch coordinates, content, or personal data are persisted.
- SuperCast's existing shell helper already detects physical input device activity. The session explicitly enables and disables its monitor through its authenticated Binder command `phone-touch-monitor` only while mirroring and brightness reduction is active. The helper reports only `phone-touch` plus monitor-ready/unavailable events, not raw input, and throttles signals to 250 ms. It tolerates absent `/dev/input` permission.
- As fallback for unsupported shell monitoring or a missing helper, existing user-enabled FT AccessibilityService now requests system `TYPE_TOUCH_INTERACTION_START/END` events and responds only to the default phone display (Android 13+). Recent FT-injected gesture timestamps are ignored to reduce false brightening from HU touch injection. Accessibility does not consume phone touch events or create an overlay.
- `MirrorTouchDimWindow` pure Kotlin policy has tests covering initial dark state, first touch, exact 30s, timer extension on more touches, stop/cancellation. Build/unit tests and physical phone/HU behavior require separate receipts.

## Risks and physical acceptance
Some Android skins do not provide Accessibility touch events, or deny physical `/dev/input` access to the shell. On those phones, "touch anywhere" cannot be guaranteed. Test (1) phone panel dark, car image unaffected; (2) physical tap brightens immediately and the tap still works; (3) repeated taps/swipes extend brightness; (4) untouched 30 s returns dark; (5) HU taps and AA navigation do not brighten the phone; (6) leave mirroring before timer expires, and after >30 s phone remains normally bright; (7) disconnect or kill FT while panel is dark/bright; restart FT and check saved brightness and auto mode recovered; (8) ICCOA and CarLife, shell helper available and unavailable; (9) toggle permission and original automatic brightness.

Nonclaims: live phone/HU field test not completed, not guaranteed on all phone models or OS versions. This is not physical panel OFF, so OLED wear may be reduced but not eliminated. No protocol bytes for ICCOA/AA/CarLife are changed.
